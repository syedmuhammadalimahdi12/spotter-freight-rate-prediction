# Freight Rate Prediction | Spotter ML Assessment

A machine learning project for predicting freight rates using historical load data. This project covers data exploration, data quality checks, feature engineering, chronological validation, model training, and final prediction generation.

## Project Overview

The objective is to predict freight rates for unseen loads using the labeled development dataset.

The solution produces:

- Predictions for 12,000 validation loads.
- Daily predictions for the 31 dates in December 2025.
- A December prediction chart generated using the assessment-provided scorer.

## Model Approach

The selected model is `HistGradientBoostingRegressor`, implemented in a scikit-learn preprocessing and modeling pipeline.

The target variable is transformed using `log1p` during training. Predictions are converted back to the original rate scale using `expm1`.

### Features

The model uses features available in the training, validation, and December datasets:

- Pickup location
- Delivery location
- Distance
- Equipment type
- Weight
- Month
- Day of week
- Day of year

Date-based features are extracted from the load date.

### Data Preparation

- Dates are converted to datetime format.
- Negative weights are treated as missing values.
- Missing numeric values are imputed using the median.
- Missing categorical values are imputed using the most frequent category.
- Categorical features are encoded using one-hot encoding.
- Features unavailable in the December input are excluded to maintain a consistent prediction pipeline.

## Training and Validation Strategy

A chronological holdout split was used to evaluate performance on a later time period.

| Dataset | Period | Rows |
|---|---|---:|
| Training | January–September 2025 | 43,147 |
| Holdout validation | October 2025 | 4,853 |
| External validation | Assessment-provided dataset | 12,000 |
| December prediction input | December 1–31, 2025 | 31 |

The model was trained on January–September data and evaluated on October data. This approach avoids randomly mixing earlier and later dates and better reflects a future prediction scenario.

After the holdout evaluation, a final model was trained using the complete labeled development dataset.

## Validation Results

The following results were measured on the October holdout dataset.

| Metric | ML Model | Median Baseline |
|---|---:|---:|
| MAE | 125.94 | 1,146.79 |
| RMSE | 647.32 | 1,567.97 |
| R² | 0.8207 | Not calculated |

The model achieved lower MAE and RMSE than the median baseline.

The difference between MAE and RMSE indicates that some individual predictions have substantially larger errors. In particular, some high-rate loads were underpredicted. This remains an area for improvement.

The final 12,000 validation predictions do not have locally available ground-truth rates. Final validation metrics are calculated by Spotter after submission.

## How to Run

### 1. Install dependencies

```bash
python -m pip install -r requirements.txt
```

### 2. Run the notebook

Open `freight_rate_assessment.ipynb` in Google Colab or Jupyter Notebook.

Upload the required assessment CSV files and update the notebook's data paths if necessary. Run the notebook cells in order to explore the data, train the model, evaluate the holdout performance, and generate the prediction files.

### 3. Run the assessment scorer

After placing `score.py`, `validation_predictions.csv`, and the completed December prediction CSV in the working directory, run:

```bash
python score.py \
  --predictions validation_predictions.csv \
  --december-predictions december-chart-inputs.csv
```

The scorer validates the prediction files and generates the December chart.

## Limitations and Future Improvements

- Evaluate additional models and hyperparameter configurations.
- Explore route-level and market-related features when they are available consistently at prediction time.
- Perform additional chronological validation across multiple time windows.
- Monitor prediction errors when actual rates become available.
