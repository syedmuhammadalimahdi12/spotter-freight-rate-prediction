## 1. Project Overview

This project develops a machine learning workflow to estimate freight load rates from historical shipment information. The workflow covers exploratory data analysis, data-quality handling, chronological model validation, model training, prediction generation, and output validation.

The solution produces:

- `validation_predictions.csv` — predicted rates for all 12,000 validation loads.
- `december-chart-inputs.csv` — predicted rates for the 31 fixed December 2025 dates.
- `candidate_december.png` — the December prediction chart generated by the supplied assessment scorer.

The supplied scorer confirmed that the final prediction files meet its structural and value requirements. Final validation performance on the hidden validation labels is determined by Spotter after submission.

## 3. Data

The labeled development dataset contains 48,000 rows. The separate validation dataset contains 12,000 loads. The fixed December prediction input contains 31 rows.

The December scenario keeps these shipment attributes fixed:

| Attribute | Value |
|---|---|
| Pickup | Lexington |
| Delivery | Fort Wayne |
| Distance | 360 miles |
| Equipment | Dry Van |
| Weight | 32,000 lb |
| Dates | December 1–31, 2025 |

Only the date changes in the December scenario.

## 4. Data Preparation and Features

The model uses features available in the training, external validation, and December datasets:

- `pickup`
- `delivery`
- `distance`
- `equipment`
- `weight`
- `month`
- `day_of_week`
- `day_of_year`

The date column is parsed as a datetime value, then calendar features are extracted. Negative weights are treated as missing values. Missing numeric values are imputed with the median, and missing categorical values are imputed with the most frequent category. Categorical variables are one-hot encoded with unknown categories ignored.

Features not present in the December input are excluded from this shared feature set so the same trained pipeline can score all three datasets consistently.

## 5. Validation Strategy

A chronological holdout split was used to approximate prediction on a later time period:

- **Training period:** January 1–September 30, 2025
- **Training rows:** 43,147
- **Holdout period:** October 1–31, 2025
- **Holdout rows:** 4,853

This avoids randomly mixing earlier and later dates and provides a more realistic time-based validation check.

## 6. Model

The solution uses a scikit-learn `Pipeline` with:

1. A `ColumnTransformer` for numeric and categorical preprocessing.
2. Median imputation for numeric columns.
3. Most-frequent imputation and one-hot encoding for categorical columns.
4. `HistGradientBoostingRegressor` as the prediction model.

The target is transformed using `log1p` during training. Predictions are converted back to the original rate scale using `expm1`.

The final model is refitted on the complete labeled development dataset before generating assessment predictions.

## 7. Holdout Results

Results on the October 2025 holdout:

| Metric | ML model |
|---|---:|
| Mean Absolute Error (MAE) | 125.94 |
| Root Mean Squared Error (RMSE) | 647.32 |
| R² | 0.8207 |

A median baseline was also evaluated:

| Metric | ML model | Median baseline |
|---|---:|---:|
| MAE | 125.94 | 1,146.79 |
| RMSE | 647.32 | 1,567.97 |

The model outperformed the median baseline on both MAE and RMSE for this holdout.

The RMSE is substantially higher than the MAE, and the error analysis identified some large underpredictions for high-rate loads. This indicates that high-value loads remain a challenging segment and should be considered when interpreting aggregate performance.

**Important:** These are local October holdout metrics. They are not metrics on the hidden 12,000-row assessment validation set. Spotter calculates final hidden-validation metrics after submission.

## 9. How to Run

### Environment

Python 3.10+ is recommended. The notebook uses pandas, NumPy, and scikit-learn. The assessment scorer uses the dependencies listed in the supplied `requirements.txt`.

Install the model and report dependencies:

```bash
python -m pip install pandas numpy scikit-learn matplotlib reportlab
```

Install the scorer dependencies:

```bash
python -m pip install -r requirements.txt
```

### Input files

Place the assessment input files in a `data/` directory, or update the notebook's `DATA_DIR` variable to match their location. The notebook currently uses these filenames:


Check the exact filenames supplied with your assessment. If they differ, either rename them or update the corresponding paths in the notebook.

### Run the notebook

Open `freight_rate_assessment.ipynb` in Jupyter or Google Colab and execute the cells in order. The notebook performs data preparation, time-based validation, model fitting, prediction generation, and output checks.

Expected output files:

```text

december-chart-inputs.csv
```

### Run the supplied scorer

After placing `score.py`, `validation_predictions.csv`, and the completed December prediction CSV in the same working directory, run:

```bash

  --predictions validation_predictions.csv \
  --december-predictions december-chart-inputs.csv
```

The scorer should create:

```text

```

Use the exact scorer command and filenames specified in the assessment README if they differ.

## 10. Limitations and Next Steps

- The hidden validation labels are not available locally, so external validation performance cannot be calculated independently.
- Large-rate loads produced some of the largest holdout errors.
- The December chart represents model predictions for the specified fixed route and shipment attributes; it is not evidence of actual realized market rates.
- Further work could evaluate additional models, investigate high-rate outliers, and compare performance across rate ranges and equipment or route segments, provided those features are available at prediction time.

## 11. Reproducibility and Integrity

The reported metrics are from the October chronological holdout produced by this workflow. The final validation and December output files were checked with the supplied assessment scorer. No claim is made about hidden-label accuracy or selection outcomes before Spotter completes its evaluation.
